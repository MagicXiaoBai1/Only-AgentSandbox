# only agent sandox 需求分析
基于firecracker snapshot恢复的高性能agent沙箱

## 部署
需要部署在arm架构的物理机或裸金属服务器上，仅需要支持linux

## 负载画像
- 要求冷启动时延尽量低
- 要求部署密度尽量高
- 一个沙箱仅仅对外提供一个SSH连接
- 沙箱要能连接互联网
- 有状态但无持久化（不能只用只读rootfs）（和serverless的区别）
- 只需要不超过100种沙箱（和serverless的区别）（我猜测沙箱种类小于10）
- 如果是openclaw小龙虾的话需要持久化有状态

## MVP阶段要求
提供三种沙箱：
- lite：2c4g
- pro：4c8g + 可读写的硬盘两个
- browser：4c8g + 可读写的硬盘一个
三种沙箱对应三种vm配置，但是操作系统镜像和只读rootfs一样。

要通过snapshot恢复技术来创建沙箱

对网络配置不做要求，但要保证后续能对接CNI插件（现在可以怎么简单怎么来）
