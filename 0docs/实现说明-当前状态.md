# 实现说明：oas-driver Shim + 自动沙箱恢复（当前状态）

> 领域术语见根目录 `CONTEXT.md`；实现计划见 `0docs/实现计划-oas-driver-shim.md`；测试见 `0docs/测试计划.md`。
> 本文记录"已经做了什么"——代码已编译通过、单元/集成测试全绿；真机端到端验证见测试计划。

## 1. 目标与范围

基于手动跑通的 firecracker snapshot 恢复流程（`0docs/生产的firecracker_snapshot恢复.md` +
`experiments/snap_double_shot`），写出自动沙箱恢复代码，打通 MVP 全链路（R2）：
**snapshot 恢复 + SSH 进 VM**，且 runtime 重启不影响已存在的 shim。

## 2. 架构（已落地）

```
kubelet ──CRI(gRPC)──> oas-runtime(进程)
                          │  RunPodSandbox 时 spawn
                          ▼ (setsid 脱离，互不连带)
                       shim(进程，每沙箱一个) ──jailer──> firecracker(进程)
                          ▲
                          │ ttrpc over UDS（Create/State/Stop）
                     oas-runtime 持 ttrpc client
```

- **runtime**：无状态调度器。`RunPodSandbox` → net.setup → storage.provision → `driver.create_vm`
  （= spawn shim + 同步 ttrpc `Create` 到 Running/Failed）→ 落库 READY。
- **shim**：广义职责，承担一个沙箱恢复全链路（materialize → jailer+firecracker → snapshot/load →
  resume → 看 fc_pid）。ttrpc sync server，`Create` 同步阻塞到就绪。
- **进程独立**：runtime 用 `pre_exec(setsid)` 拉 shim，脱离 session；jailer `--daemonize` 使
  firecracker 被 reparent 到 init。故 **shim 崩 ≠ firecracker 崩**，runtime 重启不影响 shim。
- **再发现**：runtime 启动扫 `$run_base/oas-shim-*.sock` 重建 `sid → socket` 索引（不依赖 store）。
- **可重启 + 幂等**：`Create` 自查 jail root 是否已有活 firecracker（按 `/proc/pid/root` 命中
  jail root），有则 re-attach、无则全量 restore。runtime 遇 RPC 失败 → re-spawn shim（幂等 re-attach）。
- **应急杀**：`Stop`/`delete_vm` 先试 shim ttrpc Stop；shim 不可达时直读 `shim.meta` + mntns inode
  身份校验 → 杀 firecracker → 清 jail root/socket。防 PID 复用杀错进程。

## 4. 关键设计决策（grilling 沉淀）

1. **shim 广义职责**（承担恢复全链路 1–7）——恢复状态机自包含在 shim，是 runtime 可无状态化的充要条件。
2. **ttrpc-rust sync**（非 async）——shim 是单 VM 守护进程，sync server 跑线程池最稳；runtime 侧 client 经 `spawn_blocking` 包裹。
3. **`Create` 同步到 Running/Failed**——runtime `wait_ready`/`event_fd` 退役（真实现接 `ImmediateReadiness` no-op）。
4. **进程独立 = `pre_exec(setsid)` + jailer `--daemonize`**。
5. **可重启 + 幂等 + 应急杀**——shim 崩溃可 re-spawn re-attach；firecracker 孤儿有应急杀兜底。
6. **身份校验 = mount namespace inode**（jailer chroot 必建独立 mntns，netns 不可靠）。
7. **配置 = bundle 自包含**（`$artifacts_dir/snapshots/<bundle>/{vmlinux,rootfs.ext4,vmstate,mem}`）+ `Default`/`load` 接缝 + TOML + runtime 透传 `--config`。
8. **恢复流程对齐实跑记录**：`.src` 命名、`./` 相对盘路径、保留 `--new-pid-ns`、file-only 盘、恢复只调 `snapshot/load`（不设 machine-config/drives/boot-source）。
9. **网络 = 固定 tap0 + 无 network_overrides + 静态 IP**：每沙箱 netns，firecracker 自动开同名 tap；`ip netns exec` SSH。NAT/CNI 留后期。接口 `{netns_path,tap_name}` 向前兼容 CNI。

## 6. 明确不在 MVP 范围

- **cloud_disk（块设备）恢复**——type 2 driver 返回 `Unsupported`；shim `Create` 遇 `cloud_disk_dev` 非空返回 Failed。
- **NAT/出网、CNI 对接**——接口已留 `tap_name` 前向兼容；MVP 仅 `ip netns exec` SSH。
- **vsock guest agent / 容器原语真实实现**（§2.8）——仍 no-op。
- **store ↔ driver 孤儿/降级对账**（§4.6 reconcile）——MVP 不做。
- **snapshot 在线烘焙进二进制**——用 `tools/bake_bundle.sh` 离线烘焙。
- **IdGenerator 跨进程持久化**——用 `seeded_from(store)` 近似（扫已有 id 取 max+1）；真正持久化迁 store `meta` 表后续。

## 7. 已知待真机验证的风险点

| 风险 | 处置 |
|---|---|
| `--new-pid-ns` 下 `firecracker.pid` 记 host pid 还是 ns 内 pid | 已用 `find_fc_pid`（按 mntns 命中 jail root）兜底，不依赖 pid 文件 |
| tap0 权限：jailer uid 能否开 netns 内 tap | 跟随实验（uid 1234 跑通）；不通则调 tap 所有权/CAP |
| reflink copy 需 CoW 文件系统 | `std::fs::copy` 降级普通 copy（非 reflink） |
| guest 镜像 eth0 静态 IP + sshd | 镜像侧前置，非代码范围 |
| ttrpc sync server 线程默认值 | 默认 sane，`start()` 不报错 |
