# only-agent-sandbox Runtime 概要设计 v0.2

**版本**：v0.2（基于 v0.1 + 已落地契约代码重构）
**语言**：Rust (edition 2024)，Cargo workspace
**目标**：在 Firecracker microVM 之上实现最小 CRI runtime，对接 K8s/K3s，支持 snapshot 高速恢复 + 高密度部署。

> 本文是 v0.1 的重排版，聚焦四件事：**① 分层与模块 ② 模块间接口（含接口用到的结构体）③ 每个模块的关键数据结构 ④ 关键路径**。接口签名一律以仓库内已编译通过的代码为准（v0.1 文档的 markdown 渲染曾吃掉泛型尖括号，以此版为准）。
>
> `oas-driver` 内部过程与数据结构非常复杂，本文**不展开**（见末尾“待专题”），关键路径中凡触及 driver 内部一律以 `driver.create_vm（内部略）` 表示。

## 1. 分层与模块

```plaintext
kubelet ── unix:///run/oas.sock ──► ① API/CRI 层 (oas-cri)
                                        │  proto ⇄ 内部模型 / 幂等短路 / 错误→Status
                                        ▼
                                   ② 编排层 (oas-manager)  ← 业务大脑
                                        │  状态机 + 幂等键 + ID 分配 + 后台 reconcile
                    ┌───────────┬───────┴────────┬──────────────┐
                    ▼           ▼                ▼              ▼
              ③a driver    ③b net          ③c storage       ③d store
              (oas-driver) (oas-net)        (oas-storage)    (oas-store)
              Firecracker   netns/tap/IPAM  rw-ext4/云盘     redb 持久化
              4 原语+eventfd                                  5 张表
                                        │
                                        ▼
                          带外 agent (vsock) ──回灌 exit_code/finished_at──► store
```

| 层 | crate | 模块 | 职责 | 状态 |
|----|-------|------|------|------|
| **① API/CRI** | `oas-cri` | `runtime_svc` / `image_svc` / `convert` / `error` / `unsupported` | proto⇄model 翻译、幂等短路、`OasError→Status`；不持业务状态，全委托 Manager | ✅ 已实现（StubManager 装配） |
| **② 编排** | `oas-manager` | `Manager` trait + `StubManager`；待建：`sandbox_fsm` / `container_fsm` / `reconcile` / `SandboxTypeTable` / `PerKeyLock` | 业务大脑：生命周期编排、两状态机、幂等判定、ID 分配、reconcile | 🚧 契约+Stub 已实现，真 impl 待 §3.2 |
| **③a 原语** | `oas-driver` | `FirecrackerDriver` trait + `VmId/VmStatus/VmSpec/...` | Firecracker 4 原语 + eventfd，屏蔽 snapshot/drive 细节 | 🚧 契约已实现，impl 待专题 |
| **③b 网络** | `oas-net` | `NetworkManager` trait + `NetConfig`；待建：`NetnsGuard` / tap/IPAM | netns+tap+IP/路由/NAT，snapshot 克隆可确定性重建 | 🚧 契约已实现 |
| **③c 存储** | `oas-storage` | `StorageManager` trait + `DiskConfig` | 按 type 制备 rw-ext4(COW)、绑定云盘、清理 | 🚧 契约已实现 |
| **③d 持久化** | `oas-store` | `Store` trait + `Txn`/`StoreError`；待建：`RedbStore` | redb 5 张表 Repository，事务边界=幂等与恢复原子点 | 🚧 契约已实现 |
| **共享模型** | `oas-types` | 领域 model | 跨 crate 共享 record/filter/state/metadata，无重依赖 | ✅ 已实现 |
| **装配** | `oas-runtime` | `main.rs` | 依赖注入唯一现场：open store → 注入 Manager → tonic serve UDS | ✅ 已实现（Stub） |
| **第二控制面** | guest agent（独立） | vsock 协议 | guest 内起进程、回灌 `exit_code/finished_at`、resume 后校时重连 | 🚧 待建（契约见 §2.8） |

**依赖方向（单向无环）**：`oas-cri → oas-manager → {oas-driver, oas-net, oas-storage, oas-store} → oas-types`。`oas-manager` 是唯一同时握住四个下层 trait + vsock 的枢纽。`oas-types` 不依赖任何 oas crate。

## 2. 模块间接口（契约定义）

> **约定**：所有接口用 `trait + async_trait`（`Store` 为同步 trait）表达。每个接口块内**就地声明该接口私有（crate-local）的结构体/错误类型**；接口签名中出现的 `oas_types::*` 共享类型统一在 **§2.1 共享模型** 声明，块尾用“依赖类型”一行枚举，不重复展开。

### 2.1 共享领域模型（oas-types）—— 数据字典

跨层共享，`derive(Serialize, Deserialize)`，metadata/labels/annotations 全链路原样透传（红线 1）。

```rust
// ---- IPAM 租约（net 与 store 共用）----
pub struct IpLease { pub ip: String, pub cidr: String, pub sandbox_id: String }

// ---- 状态枚举（映射 CRI proto state）----
pub enum SandboxState { Ready, NotReady }
pub enum ContainerState { Created, Running, Exited, Unknown }
pub enum ContainerExitReason { Completed, Error, OomKilled }   // 带外 agent 回灌（§4.4）

    pub type_id: u8,
    pub vm_id: u64,                      // 用 u64 而非 VmId，避免 oas-types 反向依赖 oas-driver

    pub pod_ip: String, pub gateway: String,

// ---- Filters（List* 收敛，§4.3）----

```

### 2.2 ① 对外：kubelet ↔ oas-cri（CRI gRPC）

- 传输：HTTP/2 over Unix domain socket `/run/oas.sock`。
- 契约：`0docs/cri-api_runtimev1.api.proto`（K8s `runtime.v1`，去 gogoproto 后由 `tonic-prost-build` 生成）。vendored 副本在 `crates/oas-cri/proto/api.proto`。
- 生成两个 server trait：`runtime_service_server::RuntimeService`（30 RPC）、`image_service_server::ImageService`（5 RPC），共 **35 个方法**，trait 要求全部有实现体（不支持的返回 `Status::unimplemented`）。

| 分类 | 方法 |
|------|------|
| **Runtime 真实（14）** | `Version` `Status` `RunPodSandbox` `StopPodSandbox` `RemovePodSandbox` `PodSandboxStatus` `ListPodSandbox` `CreateContainer` `StartContainer` `StopContainer` `RemoveContainer` `ContainerStatus` `ListContainers` `UpdateRuntimeConfig` |
| **Runtime unsupported（16）** | `UpdateContainerResources` `ReopenContainerLog` `ExecSync` `Exec` `Attach` `PortForward` `ContainerStats` `ListContainerStats` `PodSandboxStats` `ListPodSandboxStats` `CheckpointContainer` `GetContainerEvents`(stream) `ListMetricDescriptors` `ListPodSandboxMetrics` `RuntimeConfig` `UpdatePodSandboxResources` |
| **Image 真实（5）** | `ListImages` `ImageStatus` `PullImage` `RemoveImage` `ImageFsInfo` |

> `ImageFsInfo` 在 CRI 层直出“磁盘很空”假值，不调 Manager（防误驱逐）；`Version`/`Status`/`UpdateRuntimeConfig` 经 Manager（Stub 返回固定值）。

### 2.3 ② oas-cri → oas-manager（Manager 公开 API）

CRI 持 `Arc<dyn Manager>`，convert 后委托。Manager 方法返回 `oas_types` 的 Record，由 CRI 翻译回 proto。

```rust
// ---- 统一领域错误（自包含，不 From 下层错误，下层错误在真 Manager impl 里映射进来）----
#[derive(Debug, thiserror::Error)]
pub enum OasError {
    #[error("not found: {0}")]                 NotFound(String),          // → Status::not_found
    #[error("image not in whitelist: {0}")]    ImageNotInList(String),     // → Status::not_found
    #[error("type mismatch: {0}")]             TypeMismatch(String),       // → Status::invalid_argument
    #[error("invalid argument: {0}")]          InvalidArgument(String),    // → Status::invalid_argument
    #[error("conflict: {0}")]                  Conflict(String),           // → Status::already_exists
    #[error("unavailable: {0}")]               Unavailable(String),        // → Status::unavailable
    #[error("internal: {0}")]                  Internal(String),           // → Status::internal
}

// ---- 领域 request/response 类型（proto ⇄ domain 的 domain 侧）----
pub struct CreateSandboxRequest {
    pub metadata: SandboxMetadata, pub labels: HashMap<String,String>, pub annotations: HashMap<String,String>,
    pub hostname: String, pub log_directory: String, pub dns_config: Option<DnsConfig>, pub cgroup_parent: String,
    pub type_id: u8,               // 从 annotation `agent-sandbox/type` 解析（§9）
    pub cloud_disk_ref: Option<String>,   // `agent-sandbox/cloud-disk`
    pub rw_size: Option<u64>,             // `agent-sandbox/rw-size`
}
pub struct CreateContainerRequest {
    pub pod_sandbox_id: String, pub metadata: ContainerMetadata, pub image: String,
    pub command: Vec<String>, pub args: Vec<String>, pub working_dir: String,
    pub envs: Vec<KeyValue>, pub mounts: Vec<Mount>,
    pub labels: HashMap<String,String>, pub annotations: HashMap<String,String>,
    pub log_path: String, pub resources: LinuxResources, pub tty: bool, pub stdin: bool, pub stdin_once: bool,
}
pub struct ImageInfo { pub id: String, pub repo_tags: Vec<String>, pub repo_digests: Vec<String>, pub size: u64, pub username: String, pub image_ref: String, pub pinned: bool }
pub struct VersionInfo { pub runtime_name: String, pub runtime_version: String, pub runtime_api_version: String }
pub struct RuntimeCondition { pub r#type: String, pub status: bool, pub reason: String, pub message: String }
pub struct RuntimeStatusInfo { pub conditions: Vec<RuntimeCondition> }

// ---- Manager trait ----
#[async_trait]
pub trait Manager: Send + Sync {
    async fn version(&self) -> Result<VersionInfo, OasError>;
    async fn status(&self) -> Result<RuntimeStatusInfo, OasError>;
    async fn update_runtime_config(&self, pod_cidr: Option<&str>) -> Result<(), OasError>;

    async fn run_sandbox(&self, req: CreateSandboxRequest) -> Result<String, OasError>;          // → sandbox_id
    async fn stop_sandbox(&self, sandbox_id: &str) -> Result<(), OasError>;
    async fn remove_sandbox(&self, sandbox_id: &str) -> Result<(), OasError>;
    async fn sandbox_status(&self, sandbox_id: &str) -> Result<SandboxRecord, OasError>;
    async fn list_sandboxes(&self, filter: SandboxFilter) -> Result<Vec<SandboxRecord>, OasError>;

    async fn create_container(&self, req: CreateContainerRequest) -> Result<String, OasError>;   // → container_id
    async fn start_container(&self, container_id: &str) -> Result<(), OasError>;
    async fn stop_container(&self, container_id: &str, timeout: i64) -> Result<(), OasError>;
    async fn remove_container(&self, container_id: &str) -> Result<(), OasError>;
    async fn container_status(&self, container_id: &str) -> Result<ContainerRecord, OasError>;
    async fn list_containers(&self, filter: ContainerFilter) -> Result<Vec<ContainerRecord>, OasError>;

    async fn image_status(&self, image: &str) -> Result<Option<ImageInfo>, OasError>;
    async fn pull_image(&self, image: &str) -> Result<String, OasError>;                          // → image_ref
    async fn list_images(&self) -> Result<Vec<ImageInfo>, OasError>;
    async fn remove_image(&self, image: &str) -> Result<(), OasError>;
}
```
> 依赖类型（见 §2.1）：`SandboxMetadata` `ContainerMetadata` `DnsConfig` `KeyValue` `Mount` `LinuxResources` `SandboxRecord` `ContainerRecord` `SandboxFilter` `ContainerFilter`。
>
> `StubManager`（🚧 占位）impl `Manager`：version/status 固定、`list_*`/`image_status` 返回空、幂等 stop/remove 返回 `Ok`、写操作返回 `Err(Unavailable)`。真 Manager impl 见 §3.2。

### 2.4 ② oas-manager → ③a oas-driver（Firecracker 原语）

```rust
pub struct VmId(pub u64);
pub enum VmLifecycle { Creating, Restoring, Running, Degraded, Stopping, Stopped }
pub struct VmStatus { pub started: bool, pub healthy: bool, pub lifecycle: VmLifecycle }   // 实际态，供 reconcile 对账
pub struct VmSpec { pub rw_layer_path: Option<String>, pub cloud_disk_dev: Option<String> } // PATCH 进 snapshot 预留 drive slot

#[derive(Debug, thiserror::Error)]
pub enum DriverError {
    #[error("vm not found: {0}")]        NotFound(u64),
    #[error("vm already exists: {0}")]   Exists(u64),
    #[error("snapshot error: {0}")]      Snapshot(String),
    #[error("firecracker api error: {0}")] FirecrackerApi(String),
    #[error("io error: {0}")]            Io(#[from] std::io::Error),
    #[error("{0}")]                       Other(String),
}

#[async_trait]
pub trait FirecrackerDriver: Send + Sync {
    // 原子幂等：同 (type_id, netns) 已在建 → 返回旧 VmId；就绪写 event_fd 通知。
    async fn create_vm(&self, netns_path: &str, type_id: u8, spec: VmSpec, event_fd: RawFd) -> Result<VmId, DriverError>;
    async fn get_vm(&self, id: VmId) -> Result<VmStatus, DriverError>;
    // 幂等：删不存在返回 Ok；不保证立即停止，调用方轮询 get_vm 到 Stopped。
    async fn delete_vm(&self, id: VmId) -> Result<(), DriverError>;
    async fn list_vm(&self) -> Result<Vec<VmStatus>, DriverError>;
}
```
> `event_fd: std::os::fd::RawFd`（eventfd 异步等待）。回收边界：**VM 进程归 driver**；netns/ext4/IP 租约归编排层调 net/storage 回收，职责不重叠。

### 2.5 ② oas-manager → ③b oas-net（网络）


### 2.7 ② oas-manager → ③d oas-store（持久化）

```rust
// 占位：真实实现包裹 redb::WriteTransaction。
// ⚠️ transaction 是泛型方法 → Store 当前非 object-safe；与 §3.2 Manager 持 Arc<dyn Store> 冲突，

pub struct Txn;

#[derive(Debug, thiserror::Error)]
pub enum StoreError {
    #[error("not found: {0}")]  NotFound(String),
    #[error("io: {0}")]         Io(#[from] std::io::Error),
    #[error("db: {0}")]         Db(String),
    #[error("{0}")]             Other(String),
}

pub trait Store: Send + Sync {
    fn put_sandbox(&self, r: &SandboxRecord) -> Result<(), StoreError>;
    fn get_sandbox(&self, id: &str) -> Result<SandboxRecord, StoreError>;
    fn get_sandbox_by_uid(&self, pod_uid: &str) -> Result<Option<SandboxRecord>, StoreError>;   // ★幂等键查询
    fn list_sandboxes(&self, filter: &SandboxFilter) -> Result<Vec<SandboxRecord>, StoreError>;
    fn delete_sandbox(&self, id: &str) -> Result<(), StoreError>;

    fn put_container(&self, r: &ContainerRecord) -> Result<(), StoreError>;
    fn get_container(&self, id: &str) -> Result<ContainerRecord, StoreError>;
    fn list_containers(&self, filter: &ContainerFilter) -> Result<Vec<ContainerRecord>, StoreError>;
    fn delete_container(&self, id: &str) -> Result<(), StoreError>;

    fn lease_ip(&self, cidr: &str) -> Result<IpLease, StoreError>;       // 崩溃后不重复分配
    fn release_ip(&self, lease: &IpLease) -> Result<(), StoreError>;

    fn transaction<R, F>(&self, f: F) -> Result<R, StoreError>           // 单事务=建资源+落库原子点
    where F: FnOnce(&mut Txn) -> Result<R, StoreError>;
}
```
> 依赖类型（见 §2.1）：`SandboxRecord` `ContainerRecord` `SandboxFilter` `ContainerFilter` `IpLease`。读路径靠 redb MVCC 快照一致性，不等写锁（§4.3 PLEG 不阻塞）。

### 2.8 ② oas-manager ↔ guest agent（vsock 第二控制面）🚧 提议

控制平面走 Firecracker `virtio-vsock`（CID,port），与 SSH/业务隧道解耦。host 侧监听长存，guest 每次 resume 后主动重连 + `Hello` 认领。`exit_code` **只能**由 `Exited` 给，收不到即 `UNKNOWN`，严禁用“VM 还活着”反推 0（红线 2）。

```rust
// 提议契约（待实现）
#[async_trait]
pub trait GuestAgent: Send + Sync {
    async fn hello(&self, sandbox_id: &str) -> Result<(), OasError>;                       // resume 后认领
    async fn start_process(&self, sandbox_id: &str, req: StartProcess) -> Result<(), OasError>;  // 幂等：已起回 already-running
    async fn stop_process(&self, sandbox_id: &str, container_id: &str, sig: Signal, timeout: i64) -> Result<(), OasError>;
    async fn next_event(&self) -> Result<AgentEvent, OasError>;                            // 轮询/流式收 Exited
}
pub struct StartProcess { pub container_id: String, pub command: Vec<String>, pub args: Vec<String>, pub env: Vec<String>, pub workdir: String }
pub enum AgentEvent { Started { container_id: String, pid: u32, started_at: i64 }, Exited { container_id: String, exit_code: i32, finished_at: i64, reason: ContainerExitReason } }
```
> 依赖类型（见 §2.1）：`ContainerExitReason`；错误用 `OasError`（见 §2.3）。可靠性约定（agent 超时无 Hello→Degraded；丢连接靠 guest 重连 + reconcile 补状态）详见 v0.1 §7.3。

### 3.2 oas-manager（编排大脑）🚧
真 Manager 持四个 trait object + vsock + 类型表 + 锁：
```rust
pub struct Manager {
    driver:  Arc<dyn FirecrackerDriver>,
    net:     Arc<dyn NetworkManager>,
    storage: Arc<dyn StorageManager>,
    store:   Arc<dyn Store>,            // ⚠️ 受 Store object-safety 影响，见 §2.7
    agent:   Arc<dyn GuestAgent>,
    types:   SandboxTypeTable,          // type_id 0..=2 → 配置（启动加载，不热更）
    locks:   PerKeyLock,                // per-sandbox 串行化
}
```
- **SandboxType 表（Strategy + Registry）**：
```rust
pub struct SandboxType {
    pub type_id: u8, pub vcpu: u32, pub mem_mib: u32,
    pub snapshot_path: String,   // base snapshot
    pub rootfs_ro: String,       // 只读 rootfs.ext4
    pub has_rw_layer: bool,      // type1/2=true
    pub has_cloud_disk: bool,    // type2=true
    pub image_whitelist: Vec<String>,
}
```
| type_id | vCPU/Mem | ro rootfs | rw ext4 | 云盘 | image |
|---|---|---|---|---|---|
| 0 | 1c/512M | base-0 | — | — | img-a |
| 1 | 2c/2G | base-1 | ✓ | — | img-b |
| 2 | 4c/8G | base-2 | ✓ | ✓(Pod 注入) | img-c |

- **两个状态机**：
  - **Sandbox FSM**（映射 `PodSandboxStatus.state`）：`RunPodSandbox: net.setup→storage.provision→driver.create_vm(event_fd)→等就绪` → 成功 `READY`（写 vm_id/pod_ip/created_at）/ 失败 `NOTREADY`；`READY→StopPodSandbox→NOTREADY`；`NOTREADY→RemovePodSandbox→删记录`；reconcile 发现 VM 没了→`NOTREADY`。
  - **Container FSM**（映射 `ContainerStatus.state`，字段最严）：`CreateContainer→CREATED`（校验 image 白名单 + resources/type 一致性 + 落库）→ `StartContainer→RUNNING`（带外 agent guest 内起进程）→ 进程退出 agent 回灌 `EXITED`(exit_code/finished_at/reason) / `StopContainer`(SIGTERM→timeout→SIGKILL)→`EXITED` / VM 失联→`UNKNOWN`；`EXITED/UNKNOWN→RemoveContainer→删记录`。
- **PerKeyLock**：锁粒度 per-`sandbox_id`；锁顺序固定 `sandbox_id → container_id`；读路径不加业务锁。

### 3.4 oas-net（网络）🚧
对外结构见 §2.5。模块内关键：**`NetnsGuard`（RAII）**——所有进 netns 的 syscall 关进 `spawn_blocking` 专用线程，guard 保证 setns 一定还原：
```rust
struct NetnsGuard { host_fd: OwnedFd }   // 进入时保存 host netns fd
impl NetnsGuard { fn enter(path: &str) -> Result<Self> { /* open /proc/self/ns/net → setns(target) */ } }
impl Drop for NetnsGuard { fn drop(&mut self){ let _ = setns(&self.host_fd, CLONE_NEWNET); } }  // 出错也还原
```
> 能不 setns 就不 setns：tap 先在 host 建好，用 netlink `set link netns <fd>` 移入；只有“给 netns 内网卡配 IP/路由”绕不开才走专用线程。MAC = 固定前缀 + sandbox_id 派生（可复算不冲突）。

### 3.5 oas-storage（存储）🚧
对外结构见 §2.6。制备策略：可写 ext4 用 COW/overlay over base（reflink/qcow backing），避免每 VM 全量拷贝（高密度关键）；云盘是本地块设备直通，只“解析 annotation 设备引用 + 校验存在”，不格式化。

## 4. 关键路径

> 每条路径讲**模块间交互 + 模块内关键步骤**。凡进 `oas-driver` 内部一律标“（内部略，见 driver 专题）”。参与者简称：K=kubelet、CRI=oas-cri、MGR=oas-manager、DRV=oas-driver、NET=oas-net、STG=oas-storage、ST=oas-store、AG=guest agent。

### 4.1 节点冷启动就绪 ★最先跑
**目的**：runtime 进程拉起后对齐声明态(ST)与实际态(DRV)，再对 K 宣告就绪——**就绪前绝不 serve CRI**。
1. `main` 装配：`ST.open`(校验 schema 版本) → 注入 DRV/NET/STG/AG → 建 MGR。
2. MGR 重建内存索引：`ST → [Store::list_*] → MGR`（pod_uid↔sandbox_id、sandbox↔container_ids）。
3. 首轮强制全量 reconcile（见 §4.6）。
4. 重连控制平面：对每个 READY sandbox 等 AG 的 `Hello`：`AG → [vsock] → MGR`。
5. 对齐完成 → `Status` 才返回 `RuntimeReady/NetworkReady=true`（此前返回 `NotReady`）。
6. `K ← [CRI: Version/Status/UpdateRuntimeConfig/ImageFsInfo] → CRI → MGR`。

### 4.2 RunPodSandbox（snapshot 恢复全链路）★最核心
**阶段 A：建 microVM + 网络，返回 READY+PodIP**
1. `K → [CRI: RunPodSandbox(PodSandboxConfig)] → CRI`。
2. CRI.convert 解析 annotation（`agent-sandbox/type` 等）→ `CreateSandboxRequest`：`CRI → [Manager::run_sandbox] → MGR`。
3. MGR 模块内：取 **per-sandbox 锁** → `ST.get_sandbox_by_uid` 幂等检查（命中且健康 → 直接返回旧 id，短路，不建第二个 VM）。
4. `MGR → [NetworkManager::setup] → NET`：建 netns → tap → `ST.lease_ip` 分配 IP → 配路由/NAT → 返回 `NetConfig`。`NET → [Store::lease_ip] → ST`。
5. `MGR → [StorageManager::provision] → STG`：COW 制备 rw-ext4 + 解析云盘设备 → 返回 `DiskConfig`。
6. `MGR → [FirecrackerDriver::create_vm(netns,type_id,VmSpec,event_fd)] → DRV`（内部 snapshot load + PATCH drives + PATCH vm Resumed + 等 eventfd 就绪，**内部略**）→ 返回 `VmId`。
7. MGR 等 `event_fd`（AsyncFd 异步，不 busy-poll）→ 在**一个 ST 事务**内写 `SandboxRecord(READY, pod_ip, vm_id)`：`MGR → [Store::transaction] → ST`。
8. `K ← [CRI: PodSandboxStatus] → 读 ST` → state=READY + network.ip。

**阶段 B：CreateContainer（落库不起进程）**
9. `K → [CRI: CreateContainer] → CRI → MGR`。MGR 模块内：校验 image 命中 `image_whitelist` + resources 与 type 表**一致性校验**（不符报 `TypeMismatch`，红线）→ `ST` 写 `ContainerRecord(state=CREATED)` → 返回 container_id。

**阶段 C：StartContainer（带外 guest 内起进程）**
10. `K → [CRI: StartContainer] → CRI → MGR`。
11. `MGR → [vsock: StartProcess] → AG`。AG 在 guest 内 exec 业务进程 → 回 `Started(pid, started_at)`：`AG → [vsock] → MGR`。
12. MGR `ST` 置 `RUNNING + started_at`。`K ← [CRI: ContainerStatus] → 读 ST` → state=RUNNING。

> **失败边界**：阶段 A 任一步失败 → MGR 回滚已建资源（`NET.teardown`/`STG.cleanup`/`DRV.delete_vm`）并置 NOTREADY，留给 K 重建；`create_vm` 原子幂等，K 重试不产生第二个 VM。

### 4.3 PLEG 稳态查询心跳 ★性能命门
**目的**：K 每秒 relist/query，量大头。**全部走本地 ST，绝不打 DRV/FC**。
- `K → [CRI: ListPodSandbox/ListContainers(filter)] → CRI → MGR → [Store::list_*] → ST`（按 id/label/sandbox_id 收敛）。
- `K → [CRI: PodSandboxStatus/ContainerStatus(id)] → CRI → MGR → [Store::get_*] → ST` → 原样回填 metadata/labels/anno + state。
- `K → [CRI: Status] → 固定两 condition=true`。
> 模块内：CRI/MGR 只做 O(1) 本地读 + 原样回填；**读路径不加业务锁**，靠 redb MVCC 快照一致性；实际态新鲜度由 §4.6 reconcile 异步保证。红线：metadata 原样回填、state/exit_code 必须真实。

### 4.4 容器进程退出 / exit_code 回灌 ★重启策略命根
1. guest 内业务进程退出。
2. AG 捕获 → `[vsock: Exited(container_id, exit_code, finished_at, reason)] → MGR`。
3. MGR 模块内：取锁 → `ST` 置 `EXITED + exit_code/finished_at/reason(Completed/Error/OOMKilled)`。
4. 下一轮 PLEG：`K ← [CRI: ContainerStatus] → 读 ST` → EXITED + exit_code。
5. K 按 `restartPolicy` 决策（`OnFailure` 看 exit_code≠0）。
> 红线 2：收不到 `Exited` → state=UNKNOWN，严禁用“VM 还活着”反推 exit_code=0，否则 OnFailure 失效。

### 4.5 删除 Pod（全程幂等）
1. `K → [CRI: StopContainer(id,timeout)] → MGR → [vsock: StopProcess{SIGTERM,timeout}] → AG`；超时 MGR 兜底升级 SIGKILL → `AG → Exited → ST` 置 EXITED。
2. `K → [CRI: RemoveContainer] → MGR → ST.delete_container`（幂等：删不存在=Ok，CRI `swallow_not_found` 吞）。
3. `K → [CRI: StopPodSandbox] → MGR → [DRV::delete_vm]`（不保证立即停）→ MGR 轮询 `[get_vm]` 到 Stopped/不存在 → `[NET::teardown]`（删 netns/tap + `release_ip`）→ `ST` 置 sandbox NOTREADY。
4. `K → [CRI: RemovePodSandbox] → MGR → [STG::cleanup]`（删 rw-ext4/解绑云盘）→ `ST.delete_sandbox`。
> 回收边界：VM 进程归 DRV/FC；netns/盘/IP 归 MGR 调 NET/STG；ST 删记录。所有 Stop/Remove 幂等。

### 4.6 后台 reconcile 对账 ★声明态新鲜度来源
**目的**：周期对齐 ST（声明态）与 DRV（实际态），支撑 §4.3 读路径新鲜度 + 崩溃恢复 + 孤儿回收。MGR 独立 tokio task，每 N 秒：
```
real = DRV.list_vm()
对 ST 每条 sandbox（拿 per-sandbox 锁，仅做收敛修正）：
  VM 不存在          → ST 置 NOTREADY/EXITED（触发 K 重建）
  VM 存在 → DRV.get_vm → Degraded 映射 NOTREADY，刷新 state/health
real 中 ST 无记录（孤儿）→ DRV.delete_vm + NET.teardown + STG.cleanup
```
> 边界：reconcile 与 CRI 写共享同一把 per-sandbox 锁；reconcile 只降级/回收，不与正在进行的创建抢（避免误删在途 VM）。

### 4.7 镜像校验（退化路径）& 驱逐防护
- 起容器前：`K → [CRI: ImageStatus]` 命中白名单返回 `Image`，否则空；`PullImage` 白名单内返回 image_ref、白名单外报错；`ListImages` 返回固定白名单；`RemoveImage` 空操作（幂等）。
- 驱逐：`K → [CRI: ImageFsInfo] → 返回“磁盘很空”假值`（used<capacity），报真实/乱报都会触发误驱逐。

## 5. 横切约束（收口）

1. **双层幂等**：API 层以 K8s 身份（`pod_uid` / `sandbox_id+name+attempt`）幂等（`ST.get_sandbox_by_uid` 短路）；driver 层 `create_vm` 原子幂等。`create_vm` 成功但 commit 前崩溃 → ST 无记录 → reconcile 回收孤儿 VM。
2. **并发**：per-`sandbox_id` 锁，固定 `sandbox_id→container_id` 顺序；读路径不加业务锁。4 个必处理竞态：Run 在途 Stop 到达（Stop 排队/走删不存在=Ok）、reconcile 与 CRI 写撞（都走 ST 事务+锁，reconcile 只收敛）、同 pod_uid 并发两次 Run（命中健康→返回旧 id）、create_vm 成功未 commit 崩溃（孤儿回收）。
3. **三条实现红线**：① metadata+labels 全链路原样（convert 禁 Default 覆盖）；② exit_code 只能带外 agent 回灌；③ `List*`/`*Status` 只读 redb 不打 Firecracker，实际态由 reconcile 异步刷新。
4. **字段以目标 K8s/K3s 版本 `runtime.v1 api.proto` 为准**（已 vendored）。
